# PetAssistant 需求与设计

> 与 Claude 讨论并确定的设计文档,是后续开发的事实源。

## 1. 愿景

一个桌面小伙伴(类似 Codex 桌面端的小宠物):

- 我随时**打字**跟他说零散的话——任务、想法、事件、"这个做完了"
- 他**听懂、归类、记录**,生成结构化的文档
- 他知道我每天有哪些工作、做了哪些、哪些完成了、哪些还没有
- 他**到点提醒我**
- 他有**长期记忆**,一起工作越久越了解我
- 可配置本地模型(Ollama 等)或 API key

## 2. 定位与边界(重要)

他是**记录员 + 提醒者**,不是干活的 agent:

- ✅ 听、记、理、提醒、总结、回答"我有什么任务/我这周干了啥"
- ❌ 不写代码、不跑分析、不做大模型的重活(那些去对应项目目录开会话)

## 3. 核心设计原则:90% 确定性 + 10% 模型

| 功能 | 实现 |
|------|------|
| 到点提醒 | 定时器 + 通知,**不经过模型** |
| 任务状态管理 | 纯文件读写,**不经过模型** |
| "我今天干了啥" | 读文件回答 |
| 消息归类(任务?事件?汇报?) | 模型(小模型即可) |
| 每日总结成文 | 模型(小模型即可) |
| 伙伴式的应答 | 模型 |

模型的不可靠被隔离在低风险边缘:提醒不会因模型抽风而漏发,任务不会丢。
**因此本地 7B~14B 模型(如 Qwen)在此场景可行**;API 作为高质量模式。

## 4. 数据模型(pet-data/,唯一事实源,人类可读)

```
pet-data/
├── inbox.md        # 原始流水:- [YYYY-MM-DD HH:MM] 原话
├── tasks.md        # 任务清单,格式见下
├── about-you.md    # 对用户的长期了解
└── daily/          # 每晚一篇 YYYY-MM-DD.md
```

### tasks.md 格式

```markdown
## 待办
- [ ] T003 内容 |记录:2026-07-08 |截止:2026-07-10 |提醒:07-10 09:00

## 事件
- 2026-07-11 15:00 和管理员开会(提醒:当天 14:30)

## 已完成
- [x] T001 内容 |完成:2026-07-08
```

### daily/YYYY-MM-DD.md 格式

```markdown
# 2026-07-08 日记录
## 今日完成
## 今日新增
## 遗留(及去向:推明天/取消/继续)
## 备注(当天说过的值得留档的想法)
```

## 5. 日常节奏

- **早安简报**:当天第一条消息触发——今日到期、未完成任务(≤5 条)、昨日遗留,10 行内
- **白天**:随手丢话 → 归档 + 两行内伙伴式确认
- **晚间总结**:"总结一下今天" → 生成日记录,问遗留任务去向
- **长期**:about-you.md 持续积累(习惯、黑话、项目、人名)

## 6. 提醒机制

- **原型期(现在)**:Claude Code 的 CronCreate 定时任务 → 到点执行
  `python3 ~/.claude/branch-report/matrx_notify.py "⏰ 内容"` 推 Matrx 群
- **壳做好后**:改为 macOS 本地通知(UserNotifications),Matrx 作为离机备份通道
- 注意:Claude Code 会话是"拉"模式,不会自己开口;主动提醒必须走定时任务推送
